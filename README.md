# 塑机演示安全与商机交接

展会塑机现场的演示批准、安全冻结恢复、观看凭证、样品去向与商机授权后台。
所有示例（展商、设备、人员、客户、时间）均为虚构数据，不含真实个人信息或凭据。

## 要解决的现场问题

闭展核对时，主办方需要分别列清 **安全事件、有效演示、样品去向、经客户同意的跟进对象**，
并且每条技术问答、样品领取、报价都能证明对应「客户真正观看过的设备版本」；围观扫码不能自动变成商机。

为此系统执行以下规则：

- **设备台账**：每台塑机登记型号、展位、工艺参数范围、样料批次、模具、操作员资格、风险区域与检查版本。
- **按时段批准演示**：批准时校验操作员资格有效期、时段冲突（同设备/同操作员）、以及检查必须覆盖本场的「样料批次 + 模具」且合格。
- **安全冻结**：护罩开启、工艺参数越界、异常停机自动冻结同机同配置的受影响场次。
- **恢复必须引用新检查**：冻结场次只能凭一张晚于冻结时间、覆盖原配置的新高版本合格检查恢复；旧确认（旧检查）不得沿用。恢复产生新场次与新窗口，旧场次的扫码不自动转移。
- **观看凭证**：扫码必须落在场次窗口内，重复扫码只计一次；问答/报价/样品领取都快照该场次的设备检查版本。只有场次最终有效完成，凭证才生效。
- **样品去向**：每件样品记录生产配置、检查版本和唯一去向（发放给客户 / 展位留存 / 废弃），发放必须由本人扫码凭证支撑，且不得重复处置。
- **商机授权边界**：商机 = 明确的客户同意（留存授权表述与渠道）+ 有效观看凭证上的互动。仅有扫码记录的围观客户单独列为 bystander，不进入商机。
- **导出授权**：主办方导出闭展核对、安全员导出安全事件、展商只能导出本展位商机；越权导出一律拒绝，允许与拒绝都进审计。

## 目录

- `contracts/context.schema.json` / `fixtures/context.json` —— 原有领域上下文资料
- `contracts/exhibition.schema.json` —— 现场资料（展商、设备、事件脚本）格式
- `fixtures/exhibition.json` —— 整天现场样例：
  设备冲突排期、资格过期、检查与换料换模不匹配、重复扫码、参数越界冻结后复检恢复、
  护罩开启冻结后复检恢复、闭馆补录、异常停机、样品全去向、围观/互动/同意三类客户、越权导出
- `src/context.js` —— 领域资料读取
- `src/handover/backend.js` —— 交接后台核心规则（零依赖）
- `src/handover/replay.js` —— 按时间回放事件脚本，收集全部被拒绝的操作
- `scripts/close-show.mjs` —— 闭展核对报告
- `test/` —— 规则级单测 + fixture 端到端回放

## 运行

```bash
npm test          # 规则与端到端回放测试
npm run close-show # 输出闭展核对报告（安全事件/有效演示/样品去向/商机/审计/拒绝清单）
```

闭展报告关键输出示例（样例数据）：

- 安全事件 3 起：参数越界（冻结 S-M1-2/S-M1-3）、护罩开启（冻结 S-M2-2）、闭馆后异常停机（无进行中场次）
- 有效演示 5 场，其中 3 场为新检查恢复场（旧场次标记 superseded，凭证指向 INS-5 v3 / INS-6 v2）
- 样品 6 件全部登记去向；3 件发放均绑定领取人观看过的检查版本
- 商机 3 条（均有客户书面/电子同意）；围观客户单列，不计商机
- 被拒绝操作逐条列出：时段冲突、资格过期、检查不匹配、重复扫码、沿用旧检查恢复、冻结期登记、闭馆补录、越权导出等
