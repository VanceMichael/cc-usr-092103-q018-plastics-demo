# 塑机演示安全与商机交接

描述展会机械演示、样料、安全检查和客户交接。

## 领域资料

仓库中的 `contracts/context.schema.json` 描述基础资料格式，`fixtures/context.json` 给出可公开使用的示例。代码库只负责读取与校验这些资料，业务服务可沿用相同标识和版本约定。

当前资料反映的事实包括：

- 展商现场演示机械设备
- 客户会了解设备性能并洽谈
- 展品包含塑料中空产品

## 演示与商机交接后台

`src/index.js` 的 `createBackoffice()` 把四个模块组装成一个后台入口：

- `src/machines.js`：每台塑机保存型号、展位、工艺参数范围、样料批次、模具、操作员资格、风险区域；每次检查生成递增的检查版本，只有通过检查的设备才允许演示。换料换模会更新批次与模具，并让设备回到待检查状态。
- `src/schedule.js`：演示按时段申请与批准，自动拦截设备/操作员时段冲突与计划参数越界。护罩开启、参数越界、异常停机会冻结受影响场次；恢复必须引用一份新的、版本更高的已通过检查，旧确认单作废并留档，不得沿用。
- `src/engagement.js`：扫码 30 分钟内去重；签到把访客钉到具体场次与设备检查版本；技术问答、样品领取、报价都必须挂在有效签到上，从而证明对应客户真正观看过的设备版本。只有客户明确同意且存在有效互动才生成商机——围观扫码永远不会自动变成商机。
- `src/audit.js`：闭展核对报告把安全事件、有效演示、样品去向、经客户同意的跟进对象分别列清；导出仅限主办方（`organizer`）与安全负责人（`safety_officer`），越权导出被拦截并留痕。

样例资料：`fixtures/expo.json`（展商、设备、开幕检查），`fixtures/onsite-events.json`（一天现场事件：审批、扫码、护罩开启、冻结恢复、换料换模、参数越界未恢复、同意跟进）。`src/seed.js` 负责装载与回放。

## 本地校验

运行项目自带测试即可确认样例资料可读取，且领域标识与版本字段完整。所有示例均为虚构数据，不含真实个人信息、账号或访问凭据。

```sh
npm test        # 单元测试与一整天现场事件的集成核对
npm run report  # 回放样例事件并以主办方身份导出闭展核对报告
```
